Error pages

Break it on purpose.

Status codes must be accurate, and every error has a page. The configuration sets all 40, and each one has a real test here: what the request breaks, why that gives the code, and where the decision is made. Then trigger it.

Trigger any error

18 codes are decided by webserv itself. The other 22 are never sent by an HTTP server on its own: an application behind it decides them. For those, small CGI applications (cgi/errors/app.py) each check one real rule, and webserv serves the configured page for their answer. Trigger breaks the rule; Valid request sends one that passes the same check. Requests a browser cannot write (a broken request line, a missing Content-Length, a forbidden header) are sent raw by cgi/errors/probe.py, which shows both sides. Every tile also has the same test as a terminal command.
