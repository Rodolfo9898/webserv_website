Cookies & sessions

A game that remembers you.

HTTP forgets everything between two requests. A cookie lets the browser carry a little state around; a session keeps the real data on the server and hands the browser only an id. This clicker uses a server session when the server has one, and a plain cookie when it does not.

The cookie jar

What the browser stores for this host, and sends back as the Cookie header of every request. Add or delete one and watch the header change.

  1. 1. The first response carries Set-Cookie with a session id.
  2. 2. The browser sends it back on every request.
  3. 3. The server finds your session by that id: the score never leaves the server.

Last request to the session script

GET /cgi-bin/bonus/clicker.py reads the score, POST with click=1 or reset=1 changes it.
